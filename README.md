# №13 зертханалық жұмыс — жоба менеджерінің ЖИ-көмекшісі

Бұл жинақ **нақты GitHub API деректерін** алып, екі апталық статус-есептің тексерілетін қараламасын жасайды. Үлгідегі ойдан шығарылған сандар қолданылмайды.

## Қосу
1. Осы жинақтағы файлдарды GitHub репозиторийіңізге көшіріңіз (алдыңғы Lab10 репозиторийіне емес, жаңа `IT-Project-Lab13` репозиторийіне салуға болады).
2. `SOURCE_REPO` мәнін нақты тапсырмалар бар жобаға теңестіріңіз. Әдепкі: `margulanjanpeis-wq/DormDesk`.
3. Windows PowerShell:
   ```powershell
   python -m pip install requests
   python scripts\weekly_status.py --repo margulanjanpeis-wq/DormDesk --weeks 2
   ```
4. Есептер `reports/` бумасына шығады: екі JSON факті және екі DRAFT есеп.
5. Жергілікті Ollama орнатылған әрі модель жүктелген болса, нағыз ЖИ мәтіні үшін:
   ```powershell
   python scripts\weekly_status.py --repo margulanjanpeis-wq/DormDesk --weeks 2 --ollama-model qwen2.5:1.5b
   ```
   ЖИ қолжетімсіз болса, скрипт оны ашық көрсетіп, қалыпты фактілік мәтінге оралады.
6. GitHub Actions workflow `workflow_dispatch` және жұма сайын UTC 10:00 бойынша іске қосылады. Артефактты жүктеп, **қолмен тексеру міндетті**.

## Маңызды шектеулер
- Бұл пакет нақты GitHub API сұрауларын **сіз іске қосқанда** орындайды. Мұнда тірі деректер немесе жасанды екі спринт қорытындылары енгізілмеген.
- Actions-тың әдепкі режимі *ЖИ емес*: Ollama тек жергілікті компьютерде қолданылады. Автоматты ЖИ генерациясын хостталған ортаға көшіру үшін бөлек модель қызметі қажет.
- `opened_issues` мен `closed_issues` кезең бойынша есептеледі. CI көрсеткіштері CI болып қалады; deploy, blocked, milestone жетіспесе `null` болады.
- Бірінші орындалудан кейін verification-log және time-measurements кестелерін нақты тексеру/өлшеу арқылы толтыру қажет.
- GitHub API: `since` GitHub Issues тізімінде соңғы жаңартылған уақытқа тәуелді. Қысқа екі апталық терезеде нәтиже жазбалар тізімінен есептеледі; тарихи жабылып, кейін өзгермеген мәселелерді толық архивсіз шығару шектелуі мүмкін.
